## What was built

### 1. Prisma schema
Added `PlatformSetting` model (key/value table):
```prisma
model PlatformSetting {
  key       String   @id
  value     String
  updatedAt DateTime @updatedAt
}
```
Ran `bun run db:push` — Prisma Client regenerated to v6.19.2, SQLite DB in sync.

### 2. Settings library — `src/lib/admin/platform-settings.ts`
Single source of truth for:
- All known setting keys (15 total) organized into 3 dotted-namespace groups:
  - `platform.*` — name, supportEmail, maxProjectsPerUser, aiGenerationEnabled, registrationEnabled
  - `feature.*` — sectionAiEditing, aiWebsiteGeneration, visualEditor, customDomains, publishing
  - `design.*` — primaryColor, secondaryColor, accentColor, borderRadius
- `PlatformSettings` typed interface (camelCase fields the API returns).
- `FIELD_TO_KEY` / `KEY_TO_FIELD` bidirectional map between dotted DB keys and camelCase fields.
- `getPlatformSettings()` — reads all rows, fills missing keys with defaults, parses strings → typed values.
- `updatePlatformSettings(partial)` — validates per field (booleans accept true/"true"/1/"1"/"on"; numbers must be integer 0–10000; strings trimmed and capped at 500 chars), upserts each changed row in a `$transaction`, returns the new full typed shape.

### 3. API routes — `src/app/api/admin/`
All gated by `requireAdmin()` with the same 401-vs-403 pattern (`getServerSession` re-check distinguishes unauthenticated from authenticated-but-not-admin).

- **`GET /api/admin/settings`** → returns full typed `PlatformSettings` object.
- **`PUT /api/admin/settings`** → bulk update; body is partial `PlatformSettings`; unknown fields silently ignored; 400 on type validation errors.
- **`DELETE /api/admin/projects-all`** — Danger Zone: deletes every project NOT owned by the calling admin. Cascade (Project → Website → Page) is enforced at the schema level. Reports `deleted` + `preserved` counts. Self-protection at API layer.
- **`PUT /api/admin/reset-roles`** — Danger Zone: demotes every other admin to `user`; calling admin keeps their role. Reports `demoted` count.

### 4. Client component — `src/components/admin/admin-settings-form.tsx`
- Fetches `/api/admin/settings` + `/api/ai-info` in parallel on mount.
- 5 card sections:
  - **A. Platform Configuration** — text inputs (name, support email), number input (max projects), 2 toggles (AI generation, registration).
  - **B. AI Provider Configuration** — read-only display of active provider + configured model, with a callout: "Configure via environment variables (OPENROUTER_API_KEY, OPENROUTER_MODEL). API keys are never exposed."
  - **C. Default Design Tokens** — 3 color pickers (primary, secondary, accent) + radius presets (0/4/8/12/16/24px) + custom radius input + live preview swatches rendering actual buttons using the chosen colors and radius.
  - **D. Feature Flags** — 5 toggles (section AI editing, AI website generation, visual editor, custom domains, publishing).
  - **E. Danger Zone** — bordered card with 2 AlertDialog-gated destructive buttons (Delete all projects, Reset all admin roles).
- Sticky save bar at top with "Revert" (re-fetches) + "Save changes" (disabled when not dirty).
- Toast feedback on all save/danger operations via `sonner`.

## Security notes
- The Danger Zone endpoints preserve the calling admin's data (filter `id: { not: admin.id }`), so a bootstrap admin can wipe the platform without losing their own demo content or locking themselves out.
- API keys are never fetched, never serialized, never displayed. The AI provider section reads only from the existing read-only `/api/ai-info` endpoint (returns `provider` + `model` only).
- All admin routes re-check the DB on every request via `requireAdmin()` — a demoted admin's existing JWT stops working immediately.
- The PUT endpoint silently ignores unknown field names — no risk of writing arbitrary keys.
- Booleans normalized from `true | "true" | 1 | "1" | "on"` → `"true" | "false"`, so HTML form submissions and JSON both work.
